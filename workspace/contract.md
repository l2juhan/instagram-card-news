# 스프린트 계약

## 산출물
7장의 toss 스타일 카드뉴스 (workspace/slides.json) — 주제: 구현 상세 추상화하기

## 수락 기준

### 1. 디자인 품질 (30%)
- toss 다크 플랫 골격 + 블루 악센트 일관, Before는 빨강 / After는 그린 좌측 경계 대비
- 코드 슬라이드(3,5)의 코드블럭이 박스 안에 깔끔히 정렬 (오버플로/잘림 없음, 들여쓰기 보존)
- 빈 공간 50% 이상 슬라이드 없음 (1350px 세로 → 수직 중앙 정렬·폰트 확대로 보강)
- 타이포 위계 유지 (headline > body/code > subtext)

### 2. 독창성 (25%)
- 커버에 "X가지 방법", "알아보자", "당신이 몰랐던" 등 진부 패턴 금지
- 플레이스홀더성 텍스트 없음
- LoginStartPage/AuthGuard 사례에 특화된 구체적 표현 (일반론 나열 금지)
- 슬라이드 타입 다양성: cover/highlight/content×3/split/list

### 3. 기술적 완성도 (25%)
- 코드가 안전 마진 내 수용, 가로 잘림 없음 (가장 긴 줄도 박스 내)
- 한국어 본문 한 줄 ~15자 권장, 헤드라인 word-break 정상
- 슬라이드 타입별 필수 필드 완비, content-list item1~5 모두 채움
- 코드 원문 정확도: Frontend Fundamentals 원문과 로직 일치

### 4. 기능성 (20%)
- 1→7 서사: 통증 → 원칙 → 문제코드 → 진단 → 해결코드 → 대조 → 적용신호
- 각 슬라이드 고유 역할 (중복 없음)
- 헤드라인만으로 핵심 파악 가능
- cta 타입 미포함 (프로젝트 규칙)

## 통과 기준
- 각 축 최소 6/10, 가중 합산 최소 7.0/10
- 어떤 축이든 5 미만이면 자동 불통과

## style_override 가이드
- 허용: content 타입 → 코드블럭 변형(JetBrains Mono, 코드박스 배경/경계, 신택스 색상 span), 폰트/패딩 미세조정, 수직 중앙 정렬
- 금지: toss 브랜드 골격 변경, 대규모 재정의
- 평가자는 코드블럭 가독성·정렬·오버플로를 PNG로 직접 검증

## 하드 제약 (코드 슬라이드)
- 코드 줄 가로 오버플로 = 자동 CRITICAL
- 들여쓰기 소실 = 자동 CRITICAL
- 코드 줄 세로 잘림 = 자동 CRITICAL

## 피드백 규약
- 평가자는 슬라이드별 피드백 + 구체적 필드/변경 제안
- 생성자는 6점 미만 축 피드백 필수 반영, CRITICAL 무조건 해결
